# Протокол прогресса (шаг 7)

В прошлых роликах пользователь то и дело спрашивал «ты живой?», «покажи прогресс», «в %», «готово?», «ты закончил?». Отвечать на такие вопросы задним числом поздно: **раз в 2 минуты** в чат должна сама приходить строка с процентом и оставшимся временем.

Скрипт: `.claude/skills/stsPoetryMake/scripts/progress.py` от корня репозитория (ниже `$P`). Он хранит состояние в `<папка>/video/.progress.json`.

## 1. План с оценкой в минутах

Пробу и полный ролик веди как два отдельных прогона, потому что между ними ждём пользователя:

```bash
# проба
python "$P" init "<папка>/video" --plan "Проект и тайминги:5,Сцены пробы:15,Проверка:5,Рендер пробы:5"
# полный ролик (сцен N, тестовый рендер показал K с на 1 с видео, длина ролика D с)
python "$P" init "<папка>/video" --plan "Сцены:<N*4>,Проверка и правки:15,Черновой рендер:<оценка>,Просмотр и правки:10,Финальный рендер:<K*D/60>"
```

Минуты по плану задают вес фазы в процентах и первую оценку времени. Дальше скрипт подстраивает оценку под фактическую скорость.

## 2. Монитор, который тикает раз в 2 минуты

Сразу после `init` запусти `Monitor`:

- `command`: `python "$P" watch "<папка>/video" --every 120`
- `description`: `прогресс ролика «<название>»`
- `timeout_ms`: `1800000` (30 минут, это максимум). Когда монитор истёк, а работа ещё идёт, запусти его заново.

Монитор печатает строку раз в 120 с. Кроме того, он сразу сообщает о событиях: рендер готов (✅), рендер упал (❌), лог не обновлялся 5 минут (⚠️). Когда все фазы закрыты, монитор завершается сам.

**На каждое событие монитора** напиши в чат эту строку. Можно добавить полфразы о том, что делаешь сейчас:

> ⏳ 47% · Сцены 5/12 (мельница) · прошло 21 мин · осталось ≈ 24 мин

Если оценка заметно выросла, объясни в двух-трёх словах: «сцены сложнее, чем планировал», «рендер медленнее из-за фильтров».

## 3. Как держать состояние актуальным

```bash
python "$P" start  "<папка>/video" "Сцены" --total 12      # начать фазу (предыдущая закрывается)
python "$P" step   "<папка>/video" 5 --note "мельница"     # 5 из 12 готово
python "$P" render "<папка>/video" renders/final.log       # фаза следит за логом рендера
python "$P" done   "<папка>/video"                         # закрыть текущую фазу
python "$P" status "<папка>/video"                         # одна строка: ответ на «ты живой?»
```

- `step` вызывай после каждой готовой сцены. Цепляй его к той же команде Bash, которой проверяешь сцену, чтобы не тратить отдельный вызов.
- У рендера процент и оставшееся время берутся из строк `@hf-progress` в логе, поэтому рендер **всегда без `--quiet`**, с выводом в лог, и в фоне (`run_in_background`).

## 4. Не пропадать дольше 2 минут

- Один вызов инструмента — меньше 2 минут. Большой код делится по сцене на вызов. Всё, что дольше (рендер, транскрипция), идёт в фоне.
- Если пользователь спросил «живой?» или «прогресс?», выполни `status` и ответь его строкой сразу, без долгих объяснений.
- Пока идёт фоновый рендер и делать нечего, можно закончить ход: монитор разбудит тебя событием, ответь строкой статуса. Ход заканчивай только при живом мониторе.

## 5. В конце

`done` по последней фазе закрывает прогон, монитор выходит сам. Если он остался жив, сделай `TaskStop`. Удали `.progress.json` и `.progress.render.json`, когда ролик сдан.
