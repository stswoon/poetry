# upload-helper — инструкция для агентов

Инструмент кладёт ролик на VK Видео и RUTUBE через настоящий Chrome (Playwright).
Полное описание — [README.md](README.md). Здесь только то, что нужно агенту.

## Команды

```powershell
cd D:\mycode\poetry\utils\upload-helper
node run.js login                     # один раз, вручную: логин в оба кабинета
node run.js probe --platform vk       # снимок страницы, если сломались селекторы
node run.js upload --job <job.json>   # основная команда
```

## Job

```json
{
  "video": "D:\\...\\video.mp4",
  "thumb": "D:\\...\\oblozhka.png",
  "title": "Название стиха - Фамилия",
  "descriptionFile": "desc.txt",
  "category": "Культура",
  "playlists": ["класс-7"],
  "platforms": ["vk", "rutube"],
  "publish": true
}
```

- `video` и `thumb` можно не указывать в job, а передать флагами.
- Если `thumb` не задан — берётся единственная картинка рядом с видео.
- `descriptionFile` читается относительно папки job-файла.
- Job и описание можно сохранять с BOM — читаются нормально.

## Как понять результат

- stdout заканчивается строкой `RESULT_JSON: {...}` — это машинный итог.
- Подробности: `logs/<run>/state.json` (`stage`, `error`, `warnings`, `url`).
- Скриншоты: `logs/<run>/*.png`.
- `results[].accessConfirmed: false` — доступ «по ссылке» не подтвердился, ролик **не опубликован**
  (`ok: false`). Сообщи пользователю: доступ и публикация — вручную в кабинете.
- При ошибке: `doneOn` — где всё прошло, `retryOn` — что можно повторить.

## Правила

- Повтор после сбоя — только `--platform` из `retryOn`. Площадки из `doneOn` и с
  `accessConfirmed: false` не перезапускать: новый запуск зальёт второй ролик.
- Опечатка в `platforms` / `--platform` — ошибка (код 2), а не пропуск площадки.
- Флаги-переключатели (`--no-publish`, `--keep-open`, `--headless`) не забирают следующее слово.
- `--no-publish` держит браузер открытым (каждая площадка — своя вкладка), пока человек не
  опубликует и не закроет окно, максимум 60 минут. Запускай такую команду в фоне и скажи
  пользователю, что формы ждут его; `pendingPublish: true` в результате остаётся всегда —
  факт публикации скрипт не видит.
- Маркировку ИИ, «18+», рекламу скрипт не отмечает; отмеченные чекбоксы согласия видны в логе.
- Один запуск за раз: профиль `.profile/` не терпит параллельных окон.
- Не логиниться в этот профиль вручную во время работы скрипта.
- При ошибке «не нашёл элемент» — `probe`, затем править только `lib/selectors.js`.
- Плейлисты скрипт только выбирает; отсутствующие нужно один раз создать в кабинете.
- В описании не добавлять «Озвучено ИИ».
