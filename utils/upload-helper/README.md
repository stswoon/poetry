# upload-helper

Загрузка роликов на **VK Видео** и **RUTUBE** через настоящий Chrome (Playwright).
Логин живёт в отдельном профиле `.profile/` и переживает перезапуск браузера и скрипта.

Скрипт делает всё сам: прикрепляет файл, заполняет название и описание, ставит обложку,
выбирает категорию «Культура», доступ «по ссылке», плейлисты `класс-N` — и **нажимает «Опубликовать»**.
Публикует он только после того, как прочитал в поле «Доступ» значение «по ссылке»: если доступ
не подтвердился, ролик остаётся неопубликованным, а запуск завершается с `ok: false`.

---

## Требования

- Node.js 20+ (проверено на 24).
- Установленный Google Chrome.
- Зависимость `playwright-core` (ставится один раз: `npm.cmd install` в этой папке).
- Один раз залогиниться в профиль автоматизации — см. ниже.

Проверка:

```powershell
cd D:\mycode\poetry\utils\upload-helper
node run.js help
```

## Быстрый старт

```powershell
cd D:\mycode\poetry\utils\upload-helper

# 1. Один раз: залогиниться в VK и RUTUBE (капча/2FA — руками)
node run.js login

# 2. Проверить, что скрипт видит кабинеты
node run.js probe --platform vk
node run.js probe --platform rutube

# 3. Загрузить ролик
node run.js upload --job "D:\mycode\poetry\texts\Блок\Ночная улица\job.json"
```

`login` открывает Chrome, ты входишь в оба кабинета и жмёшь Enter в терминале.
Дальше логин сохраняется: повторять не нужно, пока сессия не протухнет.

## Формат job.json

```json
{
  "video": "D:\\mycode\\poetry\\texts\\Блок\\Ночная улица\\video.mp4",
  "thumb": "D:\\mycode\\poetry\\texts\\Блок\\Ночная улица\\oblozhka.png",
  "title": "Ночная улица - Блок",
  "descriptionFile": "desc.txt",
  "category": "Культура",
  "playlists": ["класс-7", "класс-11"],
  "platforms": ["vk", "rutube"],
  "publish": true
}
```

| Поле | Обязательно | Что это |
|---|---|---|
| `video` | да | путь к mp4 (относительный считается от папки job-файла) |
| `thumb` | нет | обложка; если нет — берётся единственная картинка рядом с видео |
| `title` | да | «Название стиха - Фамилия поэта» (VK ≤ 128, RUTUBE ≤ 100 символов) |
| `description` / `descriptionFile` | да | «Название - ФИО» + пустая строка + текст стиха |
| `category` | нет | по умолчанию «Культура» |
| `playlists` | нет | список плейлистов; выбираются только существующие (см. ниже) |
| `platforms` | нет | по умолчанию `["vk", "rutube"]`; неизвестное имя — ошибка, а не пропуск |
| `publish` | нет | по умолчанию `true` — скрипт сам жмёт «Опубликовать»; `false` = `--no-publish` |

Job-файл можно сохранять с BOM (PowerShell `Out-File`) — он читается нормально.
Флаги-переключатели (`--no-publish`, `--keep-open`, `--headless`) не забирают следующее слово;
значение — только через `=`, непонятное значение — ошибка.

Можно без файла, флагами:

```powershell
node run.js upload `
  --video "D:\...\video.mp4" `
  --title "Ночная улица - Блок" `
  --description-file "D:\...\desc.txt" `
  --thumb "D:\...\oblozhka.png" `
  --playlist "класс-7" --playlist "класс-11" `
  --platform vk --platform rutube
```

## Что именно делает upload

1. Проверяет файл (существует, формат, размер ≤ 25 ГБ), обложку и лимиты текста.
2. Открывает Chrome с профилем `.profile/` (видимое окно).
3. Проверяет, что залогинен; если нет — падает с подсказкой `node run.js login`.
4. **VK**: открывает кабинет автора, жмёт «Добавить» → «Загрузить видео», прикрепляет файл,
   заполняет название/описание, ждёт обработки, ставит обложку, выбирает плейлисты,
   на вкладке «Публикация» выставляет доступ «У кого есть ссылка» и жмёт «Опубликовать».
5. **RUTUBE**: открывает студию с окном загрузки, прикрепляет файл, заполняет название/описание,
   выбирает категорию «Культура», ставит обложку (с подтверждением кадрирования), отмечает плейлисты,
   выставляет доступ «Только по ссылке», отмечает обязательные чекбоксы согласия и жмёт «Опубликовать».
6. Забирает ссылку на ролик (обе площадки показывают её в форме ещё до публикации)
   и пишет в `logs/<run>/state.json`. У VK в ссылке остаётся `?list=ln-…` — это ключ доступа
   ролика «по ссылке», без него зритель видео не откроет.

## Доступ «по ссылке»

После выбора скрипт **читает** значение поля и считает доступ выставленным, только если там
«У кого есть ссылка» (VK) или «Только по ссылке» (RUTUBE). Перед самим кликом «Опубликовать»
значение проверяется ещё раз. Если проверка не прошла:

- ролик остаётся загруженным, но **не опубликованным**;
- в результате площадки `accessConfirmed: false` и `error`, общий `ok: false`;
- доступ выставляется и ролик публикуется вручную в кабинете — перезапуск для этой
  площадки создаст дубль.

С `--no-publish` доступ тоже проверяется: `accessConfirmed` показывает, подтвердился ли он.

## Ручная публикация (`--no-publish`)

Скрипт заполняет формы и останавливается перед «Опубликовать», а браузер **остаётся открытым**:

- у каждой площадки своя вкладка — форма VK не теряется, пока заполняется RUTUBE;
- нажми «Опубликовать» в каждой вкладке и закрой окно браузера — скрипт сразу завершится
  и напечатает `RESULT_JSON`; в терминале можно вместо этого нажать Enter;
- если ничего не делать, через 60 минут браузер закроется сам
  (`config.json → timeouts.manualPublish`);
- с `--headless` окна нет, ждать нечего — формы закрываются сразу.

Скрипт не видит, нажал ли человек «Опубликовать»: в результате у таких площадок остаётся
`pendingPublish: true`. Агенту, который запускает `--no-publish`, нужен фоновый запуск —
команда закончится, только когда человек закроет окно.

## Чекбоксы согласия (RUTUBE)

Перед публикацией скрипт отмечает в окне загрузки только чекбоксы согласия: права, правила,
условия, «ознакомлен». Маркировку ИИ, «18+», рекламу и «для детей» он **никогда не ставит**.
Подписи всех отмеченных чекбоксов пишутся в лог.

## Плейлисты

Обе площадки позволяют выбрать несколько плейлистов в форме загрузки — скрипт это делает и проверяет,
что чипы действительно появились. Совпадение точное: «класс 1» не засчитывается за «класс 11».
В RUTUBE уже отмеченный плейлист скрипт не кликает повторно — повторный клик снял бы отметку.

Скрипт **выбирает только существующие** плейлисты: создать новый из формы загрузки нельзя.
Если плейлиста нет, в `state.json` будет warning, а видео загрузится без него.

Один раз создайте набор `класс-1 … класс-11`:

- **VK**: кабинет → «Мой контент» → «Плейлисты» → «Создать плейлист» (или «+» → «Создать плейлист»).
- **RUTUBE**: Студия → «Плейлисты» → «Добавить».

Названия в `job.playlists` должны совпадать с кабинетом **посимвольно**: `"класс 1"` и `"класс-1"` — разные плейлисты.

## Обложка

- **VK**: обложка становится доступна после обработки видео — скрипт ждёт её и только потом прикрепляет.
- **RUTUBE**: после выбора файла открывается окно кадрирования — скрипт жмёт «Готово».

Площадки идут последовательно, в одном окне; с `--no-publish` каждая — в своей вкладке.
`--keep-open` при ошибке тоже ждёт, пока закроют окно (или Enter), но не дольше 60 минут.

## Результат

- `logs/<run>/state.json` — машинное состояние: `stage`, `ready`, `published`, `url`, `warnings`, `steps`, `error`.
- `logs/<run>/*.png` — скриншоты ключевых шагов (при ошибке — `error.png`).
- В конце stdout печатается одна строка:

```
RESULT_JSON: {"ok":true,"results":[{"platform":"vk","accessConfirmed":true,"url":"https://vkvideo.ru/video-...?list=ln-..."}],"stateFile":"..."}
```

При ошибке дополнительно:

- `failures[]` — площадка и текст ошибки;
- `doneOn` — площадки, где всё прошло: **их не перезапускать**, повтор зальёт второй ролик;
- `retryOn` — площадки, которые можно повторить: та же команда с `--platform <имя>`.
  Перед повтором стоит заглянуть в студию — ролик мог остаться там черновиком.

Площадки, где ролик загружен, но доступ не подтвердился, не попадают ни в `doneOn`, ни
в `retryOn`: их доделывают вручную.

Коды выхода: `0` — успех, `1` — ошибка, `2` — неверная команда.

## Если что-то сломалось

| Симптом | Что делать |
|---|---|
| «не залогинен» | `node run.js login` |
| «не нашёл кнопку/поле» | `node run.js probe --platform vk` (или `rutube`), открыть `logs/<run>/probe-*.md` и поправить `lib/selectors.js` |
| «Профиль уже занят» | закрыть окно автоматизации или другой запуск скрипта |
| Кнопка «Опубликовать» не активна | видео ещё грузится; скрипт ждёт до 30 минут (`config.json → timeouts.uploadFinish`) |
| Русский текст в консоли кракозябрами | `chcp 65001` или запуск в Windows Terminal |

Все селекторы собраны в `lib/selectors.js` — это единственное место, которое нужно править после редизайна студий.

## Ограничения и правила

- Один профиль `.profile/` — **не запускать два upload одновременно**.
- Не логиниться в этот профиль вручную, пока скрипт работает.
- Скорость загрузки = скорость браузера; для гигабайтных файлов это долго.
- Плейлисты скрипт только выбирает из существующих; отсутствующие нужно создать в кабинете один раз.
- Автоматизация — серая зона правил площадок. Не гонять пачками, темп как у человека.
- В описании не пишем «Озвучено ИИ» — по решению от 29.10.2026.

## Структура

```
upload-helper/
  run.js              # CLI: login | probe | upload
  config.json         # адреса кабинетов, лимиты, таймауты
  lib/
    browser.js        # запуск Chrome с постоянным профилем, проверка логина
    selectors.js      # ВСЕ селекторы площадок
    vk.js             # сценарий VK Видео
    rutube.js         # сценарий RUTUBE
    flows.js          # доступ «по ссылке» с проверкой, плейлисты, ожидание ссылки
    ui.js             # поиск/заполнение по списку кандидатов, чекбоксы согласия
    media.js          # проверка видео, поиск обложки, лимиты
    probe.js          # снимок страницы для починки селекторов
  .profile/           # Chrome-профиль с логинами (в git не идёт)
  logs/               # прогоны (в git не идёт)
```

Аргументы, `state.json` и чтение job-файлов — общие для всех хелперов, лежат в `utils/lib/`
(см. [utils/README.md](../README.md)).

## Для ИИ-агента: короткий контракт

1. Собери `job.json` рядом с роликом (или передай флаги).
2. Запусти `node run.js upload --job <path>` и дождись строки `RESULT_JSON`.
3. Успех — `ok: true`; ссылки на видео в `results[].url`.
4. Ошибка — прочитай `state.json` (`stage`, `error`) и последний скриншот; при «не нашёл элемент» —
   `node run.js probe --platform <...>` и правь `lib/selectors.js`.
5. Повторяй только площадки из `retryOn` (`--platform <имя>`), никогда — из `doneOn`.
   `accessConfirmed: false` — ролик загружен, но не опубликован: скажи пользователю, повтор не нужен.
6. Не запускай параллельные upload: один профиль — один процесс.
