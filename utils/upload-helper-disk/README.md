# upload-helper-disk

Бекап готовых роликов на **Яндекс Диск** в папку
[`/poetry`](https://disk.yandex.ru/client/disk/poetry).

Диск — это бекап: видео весят сотни мегабайт, в git их хранить нельзя.
Утилита работает через REST API и OAuth-токен, без браузера, Playwright и
npm-зависимостей — только Node.js 20+ и `fetch`.

Что она делает:

- загружает только видео (по умолчанию `mp4`);
- раскладывает по папкам `<Поэт>/<Стих>/`, создавая их автоматически:
  `/poetry` + `/<Поэт>/<Стих>/<файл>.mp4`, имя файла сохраняется;
- умеет загрузить один стих (`--poem`) или все стихи сразу (`--source texts`);
- пропускает уже загруженное по размеру и md5;
- проверяет файл после загрузки (размер + md5 из метаданных Диска);
- при обрыве соединения, таймауте и 429/5xx грузит файл заново (до 2 повторов);
- пишет машинный итог в `logs/<run>/state.json` и строкой `RESULT_JSON`.

---

## Требования

- Node.js 20+ (проверено на 24).
- OAuth-токен Яндекс Диска с доступом ко всему Диску.
- Свободное место на Диске.

Зависимостей нет: `npm install` не нужен.

---

## Токен

Нужен токен на **весь Диск**, а не на папку приложения: `/poetry` лежит
в корне Диска, токен с доступом только к `app:/` её не видит.

1. Создай OAuth-приложение: <https://oauth.yandex.ru/client/new>.
2. В разделе **Доступ к данным** добавь:
   - `cloud_api:disk.read` — чтение Диска;
   - `cloud_api:disk.write` — запись и создание папок;
   - `cloud_api:disk.info` — свободное место (команда `info`).
3. Скопируй **ClientID** приложения и открой:

   ```
   https://oauth.yandex.ru/authorize?response_type=token&client_id=<ClientID>
   ```

4. Скопируй выданный токен в корневой `.env` проекта (образец — `.env.example`):

   ```
   YANDEX_DISK_TOKEN=<OAuth-токен>
   ```

`.env` **не попадает в git**. Через аргументы командной строки токен не передаётся:
так он не остаётся в истории оболочки и в чате. Проверить токен и диск:

```powershell
node run.js token
node run.js info
```

Альтернатива — переменная окружения `YANDEX_DISK_TOKEN` (или `YADISK_TOKEN`):

```powershell
$env:YANDEX_DISK_TOKEN = "<OAuth-токен>"
```

Порядок поиска: переменные окружения, затем корневой `.env`.

> Токен с полными правами даёт доступ ко всему Диску пользователя. Не коммить
> `.env` и не вставляй токен в чат.

## Быстрый старт

```powershell
cd D:\mycode\poetry\utils\upload-helper-disk

# 1. Один раз: вписать YANDEX_DISK_TOKEN=<токен> в корневой .env и проверить
node run.js token

# 2. Проверить, что видно диск и папку
node run.js info

# 3. Посмотреть план по одному стиху, ничего не меняя
node run.js upload --poem "Пушкин/У лукоморья" --dry-run

# 4. Загрузить один стих
node run.js upload --poem "Пушкин/У лукоморья"

# 5. Загрузить все видео из texts (повторный запуск пропустит уже залитое)
node run.js upload --source "D:\mycode\poetry\texts"
```

Файл `texts\Пушкин\У лукоморья\lukomorye_eleven.mp4` окажется здесь:

```
disk:/poetry/Пушкин/У лукоморья/lukomorye_eleven.mp4
```

В API этот путь записывается как
`/poetry/Пушкин/У лукоморья/lukomorye_eleven.mp4`
(или `disk:/poetry/...`).

Папки `Пушкин` и `У лукоморья` создаются на Диске автоматически, если их ещё нет.

## Команды

### `token`

```powershell
node run.js token                   # проверить текущий токен
```

Сохранить или сменить токен — правкой корневого `.env`.

### `info`

```powershell
node run.js info [--remote "/poetry"]
```

Показывает занятое/свободное место, источник токена и существует ли папка на Диске.

### `list`

```powershell
node run.js list [--remote "/poetry"] [--recursive] [--limit 100]
```

Что уже лежит на Диске. `--recursive` обходит вложенные папки (до 6 уровней).

### `upload`

Один стих:

```powershell
node run.js upload --poem "Пушкин/У лукоморья"
```

Все видео из `texts`:

```powershell
node run.js upload --source "D:\mycode\poetry\texts"
```

Флаги:

| Флаг | Что делает |
|---|---|
| `--poem <Поэт/Стих>` | Загрузить один стих из `texts`. Вместо `--source` |
| `--source <путь>` | Файл или папка; можно повторять. `--file` — тот же флаг |
| `--remote <папка>` | Куда класть на Диске; по умолчанию `/poetry` |
| `--name <файл.mp4>` | Имя на Диске; только если загружается один файл |
| `--ext mp4,webm` | Какие расширения брать; по умолчанию `mp4` |
| `--all` | Брать любые файлы, не только видео |
| `--keep-root` | Добавить имя исходной папки в путь (для путей вне `texts`) |
| `--overwrite` | Заменять файл на Диске, если он отличается |
| `--no-verify` | Не считать md5, проверять только размер (быстрее) |
| `--dry-run` | Показать план и ничего не менять |

Флаги-переключатели (`--dry-run`, `--overwrite`, `--no-verify`, `--all`, `--keep-root`,
`--recursive`) не забирают следующее слово; значение — только через `=`, непонятное
значение — ошибка. Повторённые `--remote`, `--name`, `--poem`, `--job` берут последнее
значение. Файл всегда грузится целиком: загрузка кусками убрана, потому что не была
проверена на Диске.

Папку по умолчанию, список расширений и таймауты можно поменять в `config.json`.

Примеры:

```powershell
# один стих целиком (папки поэта и стиха создадутся сами)
node run.js upload --poem "Есенин/Гой ты Русь моя родная"

# один файл под своим именем
node run.js upload --source "D:\...\video.mp4" --remote "/poetry/Блок" --name "Ночная улица.mp4"

# несколько папок
node run.js upload --source "D:\...\texts\Блок" --source "D:\...\texts\Есенин"

# заменить изменившийся ролик
node run.js upload --poem "Пушкин/У лукоморья" --overwrite
```

### Job-файл

Вместо флагов можно передать JSON:

```json
{
  "poem": "Пушкин/У лукоморья",
  "remote": "/poetry",
  "extensions": ["mp4"],
  "overwrite": false,
  "verify": true,
  "dryRun": false
}
```

Или с папкой-источником:

```json
{
  "source": "D:\\mycode\\poetry\\texts",
  "remote": "/poetry",
  "extensions": ["mp4"],
  "overwrite": false,
  "verify": true,
  "dryRun": false,
  "keepRoot": false
}
```

```powershell
node run.js upload --job backup.json
```

Относительные пути в `source` считаются от папки job-файла. Флаги командной строки
перекрывают поля job-файла.

## Как строится путь на Диске

Для всего, что лежит внутри `texts`, путь всегда начинается с `<Поэт>/<Стих>`:

| Локально | На Диске |
|---|---|
| `texts\Пушкин\У лукоморья\lukomorye_eleven.mp4` | `/poetry/Пушкин/У лукоморья/lukomorye_eleven.mp4` |
| `texts\Пушкин\У лукоморья\renders\final.mp4` | `/poetry/Пушкин/У лукоморья/renders/final.mp4` |
| `texts\Есенин\Гой ты Русь моя родная\goy-ty-rus_1080p60_v2.mp4` | `/poetry/Есенин/Гой ты Русь моя родная/goy-ty-rus_1080p60_v2.mp4` |

Общая формула: **`/poetry` + `/<Поэт>/<Стих>/<файл>.mp4`**.
Если внутри папки стиха есть подпапки, они сохраняются: `renders\final.mp4`
попадёт в `<Поэт>/<Стих>/renders/final.mp4`.

Это работает и когда `--source` указывает на весь `texts`, и когда на конкретную
папку `texts\Пушкин\У лукоморья`, и когда на отдельный файл внутри неё:
утилита находит в пути папку `texts` и берёт всё после неё.

Для файлов **вне** `texts` структура считается от папки-источника; с `--keep-root`
добавляется имя самой папки-источника.

## Что именно делает upload

1. Проверяет токен и свободное место.
2. Собирает файлы: для папки — рекурсивно, по умолчанию только `mp4`.
3. Строит путь `<Поэт>/<Стих>/<файл>` и создаёт папки на Диске.
4. Смотрит метаданные целевого файла:
   - нет файла — грузит;
   - размер и md5 совпали — пропускает;
   - файл отличается — конфликт (ошибка), пока не добавлен `--overwrite`.
5. Считает md5 локального файла.
6. Запрашивает у API ссылку на загрузку и отправляет файл целиком одним `PUT`.
   При обрыве соединения (`ECONNRESET`, `EPIPE`…), таймауте или 429/5xx берёт новую
   ссылку и грузит файл заново — до 2 повторов (`retries.upload` в `config.json`).
7. Ждёт появления файла в метаданных и сверяет размер и md5. Если Диск ещё не посчитал
   md5, сверяется только размер, и это видно в выводе и в `warnings`.
8. Пишет результат в `state.json`.

Загрузка идёт последовательно, по одному файлу. Если файл уже есть на Диске и размер
совпал, локальный md5 считается только для проверки; новый файл хешируется один раз
перед загрузкой.

## Результат

- `logs/<run>/state.json` — полный машинный итог:
  `stage`, `totals`, `results[]` (`status`, `file`, `remote`, `size`, `md5`, `md5Verified`, `error`), `warnings`.
  `md5Verified: true` — md5 на Диске совпал с локальным; `false` — сверен только размер.
- В конце stdout печатается одна строка:

  ```
  RESULT_JSON: {"ok":true,"uploaded":2,"skipped":1,"conflicts":0,"failed":0,...}
  ```

Статусы в `results[]`:

| Статус | Значение |
|---|---|
| `uploaded` | файл загружен впервые |
| `overwritten` | файл заменён (`--overwrite`) |
| `skipped` | уже есть: совпал размер, а без `--no-verify` и md5 |
| `conflict` | на Диске другой файл, `--overwrite` не задан |
| `failed` | ошибка загрузки или проверки |
| `would-upload`, `would-overwrite`, `would-skip` | то же в `--dry-run` |

Коды выхода: `0` — всё хорошо, `1` — ошибка или конфликт, `2` — неверная команда.

## Ошибки и что делать

| Симптом | Что делать |
|---|---|
| `401` / «токен не принят» | Заменить `YANDEX_DISK_TOKEN` в корневом `.env` |
| `403` | Токен выдан только на папку приложения или нет прав `cloud_api:disk.write`; нужен токен на весь Диск |
| `409` «уже существует» | Файл появился между проверкой и загрузкой; запусти ещё раз или добавь `--overwrite` |
| `413` | Файл больше лимита тарифа — уменьши битрейт/размер ролика |
| `423` | Техработы или исчерпан месячный лимит загрузки Яндекс Диска |
| `429` | Слишком много запросов; утилита подождёт и повторит |
| `507` | Не хватает места на Диске |
| Ссылка на загрузку «просрочена» | Не проблема: при повторе утилита запрашивает новую (ссылка живёт 30 минут) |
| Русский текст в консоли кракозябрами | `chcp 65001` или Windows Terminal |

Ограничения Яндекс Диска: имя файла ≤ 255 символов, путь ≤ 32760 символов,
максимальный размер файла и месячный трафик зависят от тарифа.

## Структура

```
upload-helper-disk/
  run.js            # CLI: token | info | list | upload
  config.json       # API, папка по умолчанию, расширения, таймауты
  lib/
    api.js          # REST API Диска, папки, ссылка на загрузку
    upload.js       # PUT файла, повтор при обрыве, md5
    files.js        # обход папок, фильтр по расширениям, путь от texts
    token.js        # токен из env / корневого .env
    state.js        # results[] и totals поверх общего Run
    format.js       # время, прогресс
  logs/             # прогоны (в git не идёт)
```

Аргументы, чтение `.env`, HTTP с повторами, `state.json` и форматирование байтов —
общие для всех хелперов, лежат в `utils/lib/` (см. [utils/README.md](../README.md)).

## Для ИИ-агента: короткий контракт

1. Проверь токен: `node run.js token`. Если токена нет — попроси пользователя
   вписать `YANDEX_DISK_TOKEN` в корневой `.env`; сам токен не проси и не подставляй.
2. Сначала `node run.js upload ... --dry-run`, покажи план.
3. Затем `node run.js upload ...` и дождись строки `RESULT_JSON`.
4. `ok: true` — успех. `conflicts > 0` — решение пользователя: `--overwrite`
   или другое имя/папка. `failed > 0` — смотри `state.json`, поле `error`.
5. Для одного стиха используй `--poem "<Поэт>/<Стих>"`; для всех —
   `--source "D:\mycode\poetry\texts"`.
6. Не запускай два upload одновременно в одну и ту же папку.
7. Не печатай токен и не сохраняй его в файлы проекта, кроме корневого `.env`.
